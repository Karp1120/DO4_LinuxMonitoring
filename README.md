# Linux Monitoring v2.0

Этот репозиторий содержит учебный проект по мониторингу и анализу состояния Linux-системы в реальном времени.  
В ходе работы были написаны Bash-скрипты для генерации файлов и логов, очистки файловой системы, анализа логов nginx, а также настроены инструменты мониторинга **GoAccess**, **Prometheus** и **Grafana**.

Цель проекта — получить практический опыт в создании тестовой нагрузки, анализе логов, визуализации системных метрик и работе с современными средствами мониторинга Linux.

## О проекте

Во время выполнения проекта я последовательно прошёл путь от написания вспомогательных bash-скриптов до настройки полноценного мониторинга системы.  
Сначала были реализованы скрипты для генерации директорий, файлов и логов, затем — инструменты для очистки и анализа результатов. После этого были настроены системы визуального мониторинга и дашборды для отслеживания нагрузки на CPU, RAM, диск и сеть.

Проект позволил не только попрактиковаться в Bash, но и лучше понять, как организуется наблюдение за состоянием системы в реальной инфраструктуре.

## Что было сделано

### Part 1. Генератор файлов
- Написан bash-скрипт, который создаёт вложенные директории и файлы по заданным параметрам.
- Реализована работа с 6 аргументами командной строки:
  - путь,
  - количество папок,
  - набор символов для имён папок,
  - количество файлов,
  - набор символов для имён файлов и расширений,
  - размер файлов.
- Добавлены проверки корректности входных параметров.
- Реализовано формирование имён директорий и файлов по шаблону с датой.
- Учтено ограничение на остаток свободного места в разделе `/`.
- Реализовано логирование:
  - полного пути,
  - даты создания,
  - размера файлов.

Пример запуска:
`./main.sh /opt/test 4 az 5 az.az 3kb`

### Part 2. Засорение файловой системы
- Написан bash-скрипт для генерации большого количества папок и файлов в разных местах файловой системы.
- Реализована работа с 3 параметрами:
  - набор символов для имени папок,
  - набор символов для имени файлов и расширений,
  - размер файла.
- Создание происходит в случайных каталогах, кроме путей, содержащих `bin` и `sbin`.
- Количество вложенных папок — до 100.
- Количество файлов в каждой папке выбирается случайным образом.
- Добавлена остановка скрипта при достижении порога свободного места.
- В лог записываются:
  - пути к созданным папкам и файлам,
  - дата создания,
  - размер файлов,
  - время начала,
  - время окончания,
  - общее время работы.

Пример запуска:
`./main.sh az az.az 3Mb`

### Part 3. Очистка файловой системы
- Написан bash-скрипт для удаления файлов и директорий, созданных на предыдущем этапе.
- Реализованы 3 способа очистки:
  - по лог-файлу,
  - по диапазону даты и времени,
  - по маске имени.
- Добавлена возможность выбора режима очистки через параметр запуска.
- Реализована логика поиска и безопасного удаления соответствующих объектов.

Примеры запуска:
`./main.sh 1`  
`./main.sh 2`  
`./main.sh 3`

### Part 4. Генератор логов
- Написан bash-скрипт или программа, генерирующая 5 логов nginx в формате `combined`.
- Для каждого дня создаётся отдельный лог-файл.
- В каждом файле генерируется случайное количество записей от 100 до 1000.
- Для каждой записи случайным образом формируются:
  - IP-адрес,
  - HTTP-метод,
  - код ответа,
  - дата и время,
  - URL,
  - user-agent.
- Реализовано возрастание времени внутри одного лог-файла.
- Добавлены комментарии с расшифровкой кодов ответа.

Пример запуска:
`./main.sh`

### Part 5. Мониторинг логов через awk
- Написан bash-скрипт для анализа логов nginx с использованием `awk`.
- В зависимости от параметра запуска выводятся:
  1. все записи, отсортированные по коду ответа;
  2. все уникальные IP;
  3. все запросы с ошибками;
  4. все уникальные IP среди ошибочных запросов.
- Реализована работа с несколькими лог-файлами.

Примеры запуска:
`./main.sh 1`  
`./main.sh 2`  
`./main.sh 3`  
`./main.sh 4`

### Part 6. GoAccess
- Установлена и настроена утилита **GoAccess**.
- Выполнен анализ логов nginx через готовый инструмент.
- Получена та же информация, что и в скрипте из Part 5, но уже в более удобном интерфейсе.
- Поднят веб-интерфейс GoAccess на локальной машине.

Примеры команд:
`sudo apt install goaccess`  
`goaccess access.log -o report.html --log-format=COMBINED`  
`goaccess access.log --real-time-html -o /var/www/html/report.html --log-format=COMBINED`

### Part 7. Prometheus и Grafana
- Установлены и настроены **Prometheus** и **Grafana**.
- Получен доступ к веб-интерфейсам с локальной машины.
- На дашборд Grafana добавлены панели для отображения:
  - загрузки CPU,
  - свободной оперативной памяти,
  - свободного места на диске,
  - операций чтения и записи на диск.
- Во время тестов был запущен скрипт из Part 2 для искусственной нагрузки на файловую систему.
- Через Grafana отслеживались изменения в:
  - свободном месте,
  - дисковых операциях.
- Дополнительно была создана нагрузка с помощью `stress`, после чего анализировались:
  - CPU,
  - RAM,
  - disk I/O.

Примеры команд:
`sudo systemctl start prometheus`  
`sudo systemctl start grafana-server`  
`stress -c 2 -i 1 -m 1 --vm-bytes 32M -t 10s`

### Part 8. Готовый дашборд
- Установлен готовый дашборд **Node Exporter Quickstart and Dashboard** из Grafana Labs.
- Повторно проведены тесты с нагрузкой на:
  - диск,
  - память,
  - процессор.
- Запущена дополнительная виртуальная машина в одной сети.
- С помощью `iperf3` выполнен тест сетевой нагрузки.
- Через дашборд была проанализирована нагрузка на сетевой интерфейс.

Примеры команд:
`iperf3 -s`  
`iperf3 -c <ip-адрес>`  

### Part 9. Дополнительно. Свой node_exporter
- Реализован собственный скрипт или программа, собирающая базовые системные метрики:
  - CPU,
  - RAM,
  - диск.
- Метрики отдаются в формате, совместимом с Prometheus.
- Данные публикуются через nginx.
- Обновление метрик настроено с интервалом не чаще одного раза в 3 секунды.
- Конфигурация Prometheus изменена так, чтобы он собирал данные с собственного экспортера.
- Повторены тесты нагрузки из Part 7.

Примеры команд:
`sudo nano /etc/prometheus/prometheus.yml`  
`sudo systemctl restart prometheus`  
`curl localhost/metrics`
